# Правила роботи з репозиторієм

## Головні правила

1. **`main` — тільки робочий код.** Напряму в `main` не пушимо (гілка захищена).
2. **Одна картка Trello — одна гілка:** `feature/<коротко-про-задачу>`.
   Приклади: `feature/notes-search`, `feature/email-validation`, `feature/storage`.
3. **Злиття в `main` — тільки через pull request** після ревʼю тімліда (потрібне мінімум 1 схвалення).
   Тімлід може зливати власні PR без схвалення (обхід правил для адміністраторів).
5. Перед відкриттям PR переконайтеся, що програма запускається, а `flake8` не показує помилок.
6. Коли берете картку в роботу — переносьте її в **In Progress**, коли відкрили PR — у **Review**.

## Шпаргалка

### 1. Склонувати репозиторій (один раз)

```bash
git clone https://github.com/DemiD223/personal-assistant.git
cd personal-assistant
```

### 2. Почати нову задачу

```bash
git switch main          # перейти на main
git pull                 # забрати останні зміни з GitHub
git switch -c feature/notes-search   # створити нову гілку і перейти в неї
```

### 3. Зробити коміт

```bash
git status               # подивитися, що змінилося
git add assistant/notes/note.py      # додати конкретні файли
git commit -m "Додати клас Note"     # зберегти зміни з описом
```

Пишіть короткі зрозумілі повідомлення: що зроблено.

### 4. Запушити гілку на GitHub

```bash
git push -u origin feature/notes-search   # перший push гілки
git push                                  # наступні push
```

### 5. Відкрити pull request

На GitHub зʼявиться кнопка **Compare & pull request** — натисніть її,
заповніть шаблон (що зроблено, посилання на картку Trello, як перевірити)
і призначте ревʼюером тімліда.

Або з терміналу:

```bash
gh pr create --base main --fill
```

### 6. Оновити свою гілку з `main`

Якщо поки ви працювали, в `main` злили чужі зміни:

```bash
git switch main
git pull
git switch feature/notes-search
git merge main
```

### 7. Що робити при конфлікті

Конфлікт — це коли ви і хтось інший змінили одні й ті самі рядки.

1. Після `git merge main` git напише `CONFLICT` і назве файли.
2. Відкрийте файл. Ви побачите:

   ```
   <<<<<<< HEAD
   ваш варіант
   =======
   варіант з main
   >>>>>>> main
   ```

3. Залиште правильний код (можна обʼєднати обидва варіанти) і видаліть
   рядки `<<<<<<<`, `=======`, `>>>>>>>`.
4. Перевірте, що програма запускається.
5. Завершіть злиття:

   ```bash
   git add <файл>
   git commit
   git push
   ```

Якщо не впевнені — не вигадуйте, напишіть у чат команди, розберемо разом.

### Корисне

```bash
git log --oneline --graph   # історія комітів
git diff                    # що змінено, але ще не додано
git restore <файл>          # скасувати незбережені зміни у файлі
```
